Primary focus

System design for staff data engineers

The round that decides staff offers. design cases and concepts, all about moving, storing and serving data at scale. Levels 1 and 2 build the concepts in order; from level 3 you practise cases one part at a time, then whole cases scored with the staff rubric.

What a staff-level answer shows

  • Pins down scope first: consumers, freshness SLA, correctness needs, scale.
  • Sizes it: events per second, TB per day, partitions, rough monthly cost.
  • Picks batch, stream or both, and says what is given up.
  • Explains how data stays correct: idempotent writes, dedup, late data, exactly-once where it matters.
  • Plans for failure: replays, backfills, bad deploys, a region going down.
  • Covers operability: data SLOs, quality checks, alerting, on-call.
  • Thinks platform: multi-tenant, data contracts, ownership, cost per team.
  • Shows the path from today's system to the target, not only the end state.
